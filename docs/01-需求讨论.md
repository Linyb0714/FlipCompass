## 一、原始需求记录（2026-10-10 用户原话摘录）

1. 做一个 iOS 的原生 App。
2. 它是由手机四个方向的翻转，则进入对应模块。
3. 界面中由手势滑动后进行上下和前后目录的选择——这是**一级模块**。
4. 进入的**二级模块**则由我们创建的市场进行自定义。
5. 界面使用 YAML 进行读取和配置。
6. 流程：需求讨论 → 技术选型 → UX 设计（届时补充基础组件参考：RareUI、ui.watermelon.sh）→ 代码输出。

## 四、讨论记录（按轮次追加）

### 第 1 轮 · 2026-10-10
- **主题**：核心交互骨架确认（翻转机制 / 目录结构 / 模块内容 / 市场形态）
- **结论**：
  1. 翻转 = **设备物理朝向**：竖正 / 竖倒 / 横左 / 横右四个朝向各对应一个一级模块，真翻转手机即切换（陀螺仪 / 重力感应驱动）。
  2. 目录结构 = **上下滑选条目、前后滑平级切换**，两个维度均为平级浏览。
  3. 一级模块内容 = 用户已有明确设想，待下一轮描述。
  4. 市场 = **模块商店**形态（用户补充）：我们自己的市场，可以自己发起设计，也可以下载别人的；需要服务器管理、较大自由度。**一期先内置很基础的四个模块，二、三期逐步完善市场，主要交互不变。**
- **技术注意点**：iPhone 上系统不报告竖倒（portraitUpsideDown）朝向，四向翻转需基于 CoreMotion 自研朝向检测，记入《02-技术选型》待办。

### 第 2 轮 · 2026-10-10
- **主题**：交互细节层确认（翻转防误触 / 平放状态 / 前后切换对象 / 进入二级方式 / 四模块内容）
- **结论**：
  1. 翻转进入 = **翻转到位后停留 300ms 确认进入**（用户明确指定 300ms）。
  2. 平放（faceUp / faceDown）= **待机信息屏**，用户补充「简单来即可，越是简洁越是好」。
  3. 前后切换对象 = **目录页分组**：模块内目录分多页/分组，前后滑换页，上下滑选当前页内条目。
  4. 进入二级模块 = **点按确认**（上下滑选中高亮 → 点按进入）。
  5. 四个一级模块设想（用户描述）：
     - M1 **温情打卡**：今天抱抱宝宝、拥抱爱人等每日温情行动打卡，可自定义打卡项；
     - M2 **今天的想法**：一两句精言/想法记录；
     - M3 **生活助手**（待定）：搜集优惠券、旅游攻略建议、个人喜好的外卖等——用户要求我提想法；
     - M4 **随机小游戏**（待定）：类似华容道、轨道球这类小游戏——用户要求我提想法。

### 第 3 轮 · 2026-10-10
- **主题**：M3/M4 定位方案 + YAML 配置边界
- **结论**：
  1. M3 = **生活情报站**（贴用户原始设想）：优惠券/攻略建议/外卖偏好等信息卡片流；用户补充「喜好为我们记录的，数据则到时候取公共数据进行分析」——偏好数据由 App 记录，分析时取公共数据源；一期先做偏好记录+攻略收藏+好物清单，公共数据源对接二三期通过市场模块接入。
  2. M4 = **益智小游戏合集**：华容道/迷宫滚球/2048 等合集，每日随机推荐一个；用户补充「可以有当前的小游戏，交互细一点，难度中等，关数不需要太多」——首批内置小游戏，交互细腻、中等难度、少量关卡（精而不多）。
  3. YAML 配置范围 = **界面结构 + 动效参数 + 受限交互逻辑**（条件显隐、点击→跳转/提交等简单映射；不含逻辑脚本，兼顾自由度与安全）。
  4. YAML 化层级 = **一级受限模板 + 二级全 YAML**：一级模块交互骨架（翻转/手势/待机屏）原生保证体验，模块内容（目录页/条目/界面）YAML 可配；二级模块完全 YAML 渲染；市场成熟后可分发一级模块变体。

### 第 4 轮 · 2026-10-10
- **主题**：朝向映射 + 启动状态 + 层级深度 + 一期 YAML 来源
- **结论**：
  1. 朝向↔模块映射 = **竖正=M1 温情打卡 / 竖倒=M2 今天的想法 / 左横=M3 生活情报站 / 右横=M4 益智小游戏**（竖屏做记录、横屏做消费）。用户特别强调：**此处翻转交互是真机体验的核心亮点，后续需重点专项讨论怎么做合适**（已标入 UX 与技术选型重点专项）。

  3. 二级模块内部 = **支持多级页面栈**，YAML DSL 支持多页面定义，逐级返回。
  4. 一期 YAML = **全部内置随 App 打包 + 预留远程拉取接口**，一期零服务器依赖，二三期市场上线后启用分发链路。

### 第 5 轮 · 2026-10-10

- **结论**：
  1. 导航闭环 = **待机界面为零位中心**：启动先进待机界面（罗盘零位）等待手势；翻转至某朝向停留 300ms 进入对应模块；模块之间翻转直接切换（不经过待机）；**平放自动回到待机**。

  3. 最低支持 **iOS 17+**。
  4. 分发方式 = **一期内测自用**（开发者账号 + 真机调试 / TestFlight），暂不上架；二三期市场成熟后再上 App Store。
  5. 目标用户 = **先自用打磨**（自己和家人），成熟后再扩大用户面。
- **需求阶段小结**：五轮讨论覆盖交互骨架、交互细节、模块定位、YAML 边界、朝向映射、导航闭环与平台边界，需求骨架全部确认。遗留细节已归档至对应阶段（技术选型 / UX / 二三期市场），**可进入技术选型阶段**。

### 第 6 轮 · 2026-10-12（交互细化 · 已完成）
- **主题**：转场与切换动效风格（用户提出两点）
- **用户原话**：
  1. 「需要每个模块都有一个元素带入下一级，而不是跳转和遮罩」
  2. 「切换时采用碰撞，或者是 icon 的跳跃出来 3D 的效果」
- **结论**：
  1. **带入主体 = 选中卡片生长**（一级→二级）；用户补充带入意象从待机就开始：待机屏四模块 icon、或「主题色水滴跳入晕染开」带入模块（主题色水滴晕染成为贯穿全 App 的品牌转场语言候选）。
  2. **应用层级 = 统一风格**：待机→模块、模块↔模块翻转、一级→二级全部采用同一物理感风格。
  3. **主基调 = 碰撞**（实体撞击感，果断有力），icon 3D 跳跃作为辅助表达。
  4. **返回 = 元素原路收回**（对称 hero，二级收回成一级卡片/icon，空间连续闭环）。
  5. **实现路径 = 保持 iOS 17+ 自研**（matchedGeometryEffect），风格完全可控（碰撞/3D/晕染均可定制），不用 iOS 18 原生 zoom API，最低支持版本不变。

### 第 8 轮 · 2026-10-12（主交互深化 · 已闭环）

3. **草稿永久保留**：回到原界面永远在，用户主动删除/发布才清。
