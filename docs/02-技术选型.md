### 2. 四向翻转交互专项 ⭐（用户指定的核心亮点 · R8 判定模型已确认）

**翻转判定算法 v2（R8 已确认，替代单 300ms 计时）**

人翻手机的自然动作 = 快速旋转 → 自然减速 → 稳稳停住；而误触 = 躺卧缓慢晃过某朝向 / 连续翻转不停留。判定模型升级为四态状态机：

```
IDLE ──角速度超阈值(主动翻转动作)──▶ FLIPPING
FLIPPING ──角速度自然衰减──▶ SETTLING（减速停驻）
SETTLING ──朝向稳定+自适应停留窗口──▶ CONFIRMED（进入模块）
任意态 ──长时间不稳定──▶ 回 IDLE
```

- **自适应停留窗口**：干脆俐落的快翻+停稳 → 短窗口（约 150~200ms，响应爽快）；无明确翻转动作的缓慢倾斜 → 长窗口或不确认（防误触）——「根据当前人的自然响应」的实现
- **翻转过程预反馈**：FLIPPING/SETTLING 期间目标模块边缘亮起/主题色微渗（渐进预览），停稳即入，不中断体验
- 迟滞角度（hysteresis）防朝向边界抖动；faceUp/faceDown（平放）单独分支 → 待机
- CoreMotion 数据源：CMDeviceMotion 的 rotationRate（角速度）+ gravity（朝向），更新频率 60Hz 档
- **调试日志体系（R8 用户要求）**：真机调试期间，将判定过程全量记录为结构化调试日志（时间戳、角速度曲线、朝向角度、状态机迁移、窗口时长、触发/未触发原因），导出分析作为参数调优与后续优化的决策依据；日志仅存本地（隐私），提供开关
- 全部参数（角速度阈值/衰减阈值/自适应窗口极值）真机调优，需用户 iPhone 配合

**技术可行性**：✅ 全部为公开 API，无障碍；难点在参数手感调优（真机专项）

### 6. 转场与切换动效专项（R6 已确认 · 2026-10-12）

**一级→二级及全层级 Hero 转场（元素带入，非跳转非遮罩）**
- ✅ 实现路径已定：**iOS 17+，matchedGeometryEffect 自研**（不用 iOS 18 原生 zoom API，最低版本不变）
- 自研要点：手势驱动/中断恢复（用户反转可取消）、转场进度实时跟手、性能监控（全程60fps）
- 转场层级与形态（R6 确认）：
  - 待机→模块：首页模块 icon / 主题色水滴跳入晕染开带入
  - 模块↔模块翻转：碰撞登场（新模块入、旧模块被撞开）
  - 一级→二级：选中卡片生长满屏
  - 二级→一级：元素原路收回（对称 参数复用，动画反向播放）

**碰撞 / icon 跳跃 3D 动效（碰撞为主基调）**
- iOS 17+ `KeyframeAnimator` / `PhaseAnimator` 关键帧动画（弹跳节奏、overshoot 回弹曲线）
- 碰撞感：自研弹簧物理（`spring(response:dampingFraction:)` 硬弹簧）或 UIKit Dynamics 可选；碰撞节奏参数（力度/反弹次数）需真机调优
- 3D 纵深感：Z 轴 scale 起跳 + 落地、阴影/景深模糊强化纵深（用户偏好 3D 立体感，不用倒影）
- 水滴晕染实现候选：SwiftUI Canvas / Metal shader 绘制扩散晕染，或形变动画+模糊扩散渐变；需与主题色体系联动（每模块主题色→水滴色）
- 与 YAML 边界对齐：转场动效参数（时长/弹性/碰撞力度/晕染范围）纳入「YAML 动效参数」可配置范围

### T1 · 2026-10-12（工具链 / 架构 / 多朝向渲染 / 工程结构 · ✅ 已定稿）

**结论**：
1. **工具链**：Intel MacBook Pro（macOS 13.5）+ **Xcode 15** + iOS 17 SDK；真机 **iPhone 14 Pro Max**（A16，ProMotion 120Hz——对碰撞/回弹动效手感有实质加成）。
2. **多朝向渲染 = 方案 B 受控系统旋转**：MotionKit 四态判定确认后 `requestGeometryUpdate` 解锁朝向，键盘/系统 UI 永远正确；碰撞/水滴效果叠加图层实现。用户补充两点：① **旋转系统层也要数据日志**（requestGeometryUpdate 调用时机/结果/失败原因/旋转锁冲突表现），与 R8 MotionKit 判定日志同入调试日志体系，用于后续优化；② **初次进入使用时要有简单的气泡引导**（已转记需求侧 #21，UX 阶段设计）。
3. **架构 = 原生 SwiftUI + @Observable + 轻量 MV + 服务层**，零第三方依赖（除 Yams）。
4. **工程结构 = 单 App target + 分层文件夹起步**；用户约束：**后续有拆分需求，每个框架/依赖选择必须考虑 SPM 兼容性**（Yams ✓ SPM 原生支持），分层保持单向依赖、可随时拆本地 SPM 包。

**依赖清单定稿**：Yams（唯一第三方）+ SwiftUI / SwiftData / CoreMotion / Combine（系统框架）。

**待验证风险点（编译后首批真机验证，已列入清单）**：
- iPhone 实际支持 portraitUpsideDown 声明；
- requestGeometryUpdate × 系统「竖排方向锁定」冲突行为（降级策略：提示解锁或临时自绘）；
- 系统旋转动画与碰撞/水漏叠加图层的时间轴编排。

### T2 · YAML DSL 专项设计（2026-10-12 · ✅ 已定稿）

**结论**：
1. **语法风格定稿**：`pages`（多页定义，多级页面栈靠 navigate 在页间跳）+ `layout`（嵌套容器/children）+ `bind`（$draft.*/${item.*} 插值/provider 数据源）+ `onTap`（动作内联）四段式。
2. **组件 v1 定稿 = 4 布局 + 14 基础组件**：
   - 布局：vstack / hstack / list / grid
   - 基础：text / image / icon / card / button / text-editor / tag-picker / toggle / slider / progress / empty-state / **calendar-heatmap（日历热力图，用户补充）** / **countdown-card（倒计时卡，用户补充）**
3. **市场模块数据边界 = 预留网络字段、一期不实现**：DSL 语法层预留 `network` 声明位，运行时忽略并标记「未启用」，避免后期 DSL 改版；市场模块一期只可访问自己的本地 KV + 声明的 Provider。
4. **安全模型**：组件注册表闭合集 + 动作白名单闭合集（navigate/pop/submit/toggle/setValue/haptic）+ 数据隔离（模块 KV + Provider 声明制）——市场 YAML 天生无法执行任意代码。
5. **渲染管线**：Yams 解析 → IR（强类型中间层，可单测/服务端可复用）→ 组件注册表 → SwiftUI 树。
6. **动效词汇表**与 R6 转场体系一一对应：collide-in / collide-pop / drop-bloom / grow-hero / spring-pop / shrink-away，参数（强度/时长/方向）可配。
7. **包格式**：模块 = 文件夹（module.yaml manifest + pages/ + assets/），一期 Bundle 内置、二期市场下载同构零改动。

### T3 · 数据模型设计（2026-10-12 · ✅ 已定稿，含自查修订）

**结论**：
1. 实体清单认可 + 用户要求自查 → 发现 3 遗漏 1 盲点，终版 **14 实体**：
   - M1：CheckInItem / CheckInRecord；M2：Thought

   - 市场预留：ModuleKV / **InstalledModule**（安装登记）
